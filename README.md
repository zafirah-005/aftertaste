# Aftertaste

An early-warning web app that flags possible food and water contamination outbreaks before they spread. Health workers report case counts per village, and Aftertaste compares each village against its own normal level, raises alerts on unusual spikes or neighbouring villages rising together, and explains each alert in plain English.

All data is mock data. No real patient information is used.

## Features

- **Report form** – log symptom type (diarrhoea, vomiting, fever, other), number of cases, village/pincode and date.
- **Spike detection** – each village's cases today are compared with its own 14-day rolling average using a z-score. Far above normal creates an alert, and slightly above normal marks the village as rising.
- **Cluster detection** – two or more villages in the same pincode prefix rising together create a cluster alert.
- **Live map** – Leaflet + OpenStreetMap (no API key). Each village is a dot that is green (normal), amber (rising) or red (alert). Dot size scales with case count, alert dots glow and pulse, and clicking a dot shows a 7-day history.
- **Cluster network view** – a dark, force-directed graph of villages. Nodes are draggable and stay where dropped. Edges connect villages that share a pincode prefix. Edges touching an alert turn red, neighbours of an alert get an amber "watch" ring, and a ripple fires when a village turns red. Click a node for a side panel with its status, AI explanation and 14-day sparkline.
- **Alert panel and verification queue** – every alert starts as "needs checking". Officers mark it Confirmed, Investigating or False alarm, and the status is saved.
- **AI explanations** – each new alert gets one plain-English sentence describing the pattern, generated by an LLM on Groq. If the call fails or times out, a template sentence built from the same numbers is used, so the app never errors.
- **Simulate outbreak** – sends a burst of fake reports to one village over a few seconds so you can watch it turn from green to red live, with a new alert appearing. Available from the header and from the cluster network view (which also zooms to the affected area).
- **Charts** – per-village line chart of daily cases vs expected level (dashed), and a bar chart of total cases by village sorted highest first.

## How detection works

1. For each village, take the daily case totals for the previous 14 days. The mean is the expected level and the standard deviation (floored at 1) is the spread.
2. Compute `z = (today - mean) / std`.
   - `z >= 3.0` → **alert** (red)
   - `z >= 1.5` → **rising** (amber)
   - otherwise → **normal** (green)
3. Confidence is the normal CDF of `z`, capped at 99.9%.
4. Villages are grouped by the first 3 digits of their pincode. If 2 or more in a group are rising or in alert, each gets a **cluster** alert.
5. Detection runs whenever villages are fetched or a report is posted. An alert is created once per village, type and day, and its AI explanation is generated only when the alert is first created.

## Running locally

You need Python 3.10+ and Node.js.

### 1. Backend

```
cd backend
python -m venv venv
venv\Scripts\activate          # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
```

Create `backend/.env` (optional, see below), then start the server:

```
uvicorn app.main:app --reload --port 8001
```

The SQLite database is created and seeded automatically on first start.

### 2. Frontend

In a second terminal:

```
cd frontend
npm install
npm run dev
```

Open the URL Vite prints (usually http://localhost:5173). The frontend talks to `http://localhost:8001` by default. To use another backend URL, set `VITE_API_URL` before running `npm run dev`.

### AI explanations (optional)

Create `backend/.env` with a Groq API key from https://console.groq.com:

```
GROQ_API_KEY=your-key-here
```

Without a key the app works normally and uses the template explanation sentence. `.env` is gitignored and must never be committed.

## API

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/api/villages` | Villages with today's cases, baseline, status, confidence and total cases |
| GET | `/api/villages/{id}/history?days=30` | Daily cases and expected level for a village |
| POST | `/api/reports` | Submit a case report |
| GET | `/api/alerts` | List alerts (optional `?status=`) |
| PATCH | `/api/alerts/{id}` | Set alert status: `needs_checking`, `investigating`, `confirmed`, `false_alarm` |

## Trying it out

1. Open the app and switch between **Map view** and **Cluster network**.
2. Click **Simulate outbreak** and watch the chosen village turn red, an alert appear with its explanation, and (in the network view) its neighbours get watch rings.
3. Mark the alert Confirmed, Investigating or False alarm.
4. Submit your own report from the form and see the map and charts update.

## Notes

- Villages and pincodes are fictional and placed around Pune, Maharashtra for demo purposes.
- Alerts are a screening aid, not a diagnosis. Explanations describe case-count patterns only and make no medical claims.
